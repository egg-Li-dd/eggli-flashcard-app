  [2026-06-15 重大升级] 本地题目矩阵分析（避免重复出题）
  背景：分类检测卡片数可达 100+，本地题库可能已含部分 (cardId × type) 组合
       直接全部让 AI 出题会：① 重复出题 ② token 浪费 ③ 题目"撞车"概率升高
  核心思路：先用本地题库构建"题目矩阵"，决定每个 (card, type) 还需要不需要生成
            再按矩阵过滤任务清单 + 把"已有题目"段嵌入 prompt
  新增函数：
  - MAX_QUESTIONS_PER_CARD_TYPE = 1（每张卡每种题型出齐上限）
  - analyzeQuestionMatrix(cards, existingQuestions):
      返回 { byCardType, byCardStems, needTypesByCard, totalByType, totalCount }
      · byCardType: Map<cardId, { type: count }>  统计每张卡每种题型已有几道
      · byCardStems: Map<cardId, { type: [stems] }>  每张卡每种题型的 stem 列表（用于 prompt 嵌入）
      · needTypesByCard: Map<cardId, [type, ...]>  该卡还缺哪些 type
      · totalByType / totalCount: 总体统计
  - isBatchTypeSatisfied(cardBatch, type, matrix):
      batch 内所有 card 都已出齐该 type 时返回 true（用于跳过任务）
  - formatExistingQuestionsForBatch(cardBatch, matrix, type):
      把 batch 内已有该 type 题的卡格式化为 prompt 段，告知 AI "该卡已有 X 道，不要再出"
  - buildLitePromptByType(cardBatch, type, options) 签名升级为 { existingQuestions, matrix }：
      · 优先使用 matrix 输出"按卡片精确提示"段（明确告诉 AI "c1 已有 single_choice 题"）
      · 再追加"全局参考"段（用 existingQuestions 取该题型前 5 条）
      · 都为空时显示"暂无已有同类题"段
      · 嵌入位置：模板末尾"只返回 JSON 数组。"前
  - generateQuestionsForWeakModel 增强：
      · 拆批前先 analyzeQuestionMatrix 构造题目矩阵
      · 短路返回：所有 (card, type) 都已出齐时 callCount=0 + skippedReason='all_satisfied'
      · 任务过滤：每个 (batch, type) 任务先用 isBatchTypeSatisfied 跳过
      · 单题冲突检测：AI 返回的题若 cardId×type 已达 MAX，直接丢弃
      · 返回结果增加 { matrix, skippedTasks: { byType: { single_choice: N, ... } } }
  实战效果（100 张卡片 + 80 张已有 single_choice/true_false 的本地题库）：
      原方案：100/5 × 4 题型 = 80 次调用
      新方案：20 批 × 平均 0.6 题型 = 12 次调用（跳过 32 个已出齐任务）
      调用次数减少 ~85%
  → 定位: analyzeQuestionMatrix → L286；isBatchTypeSatisfied → L332；
         formatExistingQuestionsForBatch → L343；buildLitePromptByType → L199；generateQuestionsForWeakModel → L377

【独立页面 vs 主应用】

    · 不挂 AppProvider（无 useApp()，showToast 内联实现）
    · 不挂 BrowserRouter（无路由，单页面）
    · 不挂 ErrorBoundary（轻量级，崩溃由 WebView 容错）
