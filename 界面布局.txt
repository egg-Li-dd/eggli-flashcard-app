# ─── 通用防御层 (长按文本选择禁止) ───

## 第一层: 全局 CSS (src/index.css)
  *: user-select:none; -webkit-user-select:none; -webkit-touch-callout:none;
  html/body/#root: user-select:none; touch-action:manipulation;
  例外: input/textarea/[contenteditable="true"] 允许文本选择

## 第二层: 全局 JS 事件 (src/App.jsx AppShell 内 useEffect)
  document.addEventListener('contextmenu', handleContextMenu, { passive:false })
  document.addEventListener('selectstart', handleContextMenu, { passive:false })
  过滤条件: 若非 INPUT/TEXTAREA/contenteditable → preventDefault()

## 第三层: 组件级 onContextMenu / onSelectStart
  每个页面根 div 均挂载 preventTextMenu()
  CardItem 组件 (src/components/CardItem.jsx) 额外加 WebkitUserSelect: 'none'

## 2. 分类详情页 (src/pages/Category.jsx)
  路由: /category/:id
  布局: 全屏容器 (flex column)
    - 顶部 Header: 返回按钮 + 分类名 + 操作按钮
    - 主内容: 单元概览下拉导航 + 卡片列表 (CardItem compact 模式)
    - 底部: 输入栏 (InputBar) 或右侧悬浮输入栏 (FloatingInputBar)
      · InputBar 主行: [▾工具栏] [textarea(含展开图标)] [🎤] [↑]
      · textarea 自动扩展 min 1行 / max 3行
      · 展开图标 ↗  底部滑入面板（编辑文本弹窗 → 确认/取消）
    - 知识点确认弹窗 (KnowledgePointConfirm):
      · 触发: AI 生成卡片前，先确认拆分出的原始知识点
      · 层级: overlay zIndex=120，高于底部固定输入栏 zIndex=30
      · 内容: 顶部标题 + 中部知识点列表单独滚动 + 底部粘性操作栏
      · 底部按钮: sticky bottom + safe-area，保证“确认并生成卡片”在手机端与内置浏览器小视口中可见
      · 数据: 用户确认/编辑后的每条知识点会按顺序强制写入生成卡片的 knowledge_point
    - 卡片编辑弹窗 (CardItem):
      · 入口: 卡片右下角“更多操作” → “编辑问题和答案”
      · 原始知识点 textarea: 默认显示 card.knowledge_point
      · 保存: 同步写回 knowledge_point / front / back
    - 指定分类归类流程（任务 3）:
      · 入口: 单元概览右侧菜单 → “指定分类归类”
      · 第一步: CardSelectionModal 底部抽屉，按单元分组选择卡片，支持全选/反选/翻转查看原始知识点，底部“下一步”按钮
      · 第二步: TargetCategorySelect 居中弹窗，显示所有分类及卡片数量，支持新建分类；底部固定"上一步 / 下一步"按钮，按钮最小高度 50px
      ·   TargetCategorySelect 弹窗高度改为 min(calc(100dvh - 32px), 820px)，宽度 100%，圆角 20px；内容区 padding 18px；分类选项按钮 minHeight 60px；顶部标题区 padding 20px；三段式 flex column，header/footer flex-shrink: 0
      · 第三步: UnitReorganizeConfirm 确认 AI 生成的目标分类单元方案，可编辑单元名，确认后执行移动
      · 完成: 自动导航到目标分类详情页，并通过 Toast 显示移动成功、原空分类删除等结果
    - AI 全权归类流程（任务 4）:
      · 入口: 单元概览右侧菜单 → “AI 全权归类”
      · 第一步: CardSelectionModal 选择跨分类重新规划的卡片，底部“下一步”触发 AI 生成全量分类方案
      · 第二步: CrossCategoryConfirm 居中弹窗，展示“分类 → 单元 → 卡片”三级折叠结构
      · 编辑: 分类名输入框 minHeight 48px（分类）/ 46px（单元），字号 15-16px，padding 10px；卡片 minHeight 64px
      · 卡片点击后在题目 / 原始知识点之间翻转（翻转后字号加粗区分度更强）
      · 分类折叠按钮 44x44，单元折叠按钮 42x42
      · 底部: 取消 / 确认执行按钮 sticky bottom + safe-area，按钮最小高度 50px
      · 完成: 创建新分类和新单元，移动卡片，清理原空单元/空分类，导航回首页分类列表
    - 三个智能归类入口移动端滚动修复（2026-06-15）:
      · 入口: "智能单元整理" / "指定分类归类" / "AI 全权归类"
      · CardSelectionModal: 抽屉高度使用 86dvh，内容区 data-mobile-scroll="card-selection-content"，明确 touch-action: pan-y + overscroll-behavior: contain
      · TargetCategorySelect: 弹窗高度改为 min(calc(100dvh - 32px), 820px)，宽度 100%，圆角 20px；三段式 flex column（header/footer flex-shrink: 0），内容区 overflowY: auto + padding 18px；分类选项按钮 minHeight 60px；底部操作栏按钮 minHeight 50px
      · UnitReorganizeConfirm: 弹窗高度 min(calc(100dvh - 32px), 820px)，顶部标题区 padding 20px（图标 48px + 标题 19px + 副标题 14px）；内容区 padding 18px；单元名输入框 minHeight 48px，字号 16px，加粗 700；卡片按钮 minHeight 64px；底部操作栏 flex-shrink: 0 + 按钮 minHeight 50px；三段互不叠加
      · CrossCategoryConfirm: 弹窗高度 min(calc(100dvh - 32px), 820px)，顶部标题区 padding 20/20/16（图标 48px，标题 19px）；分类名输入框 minHeight 48px，单元名输入框 minHeight 46px；分类折叠按钮 44x44，单元折叠按钮 42x42；卡片按钮 minHeight 64px；内容区 overflowY: auto + padding 18px；底部操作栏按钮 minHeight 50px；三段互不叠加
      · 核心防叠加策略: 所有弹窗容器 overflow: hidden + 三段式 flex column；header/footer 显式 flex-shrink: 0；内容区 flex: 1 + overflowY: auto，保证滚动独立、操作区永远可见
      · 关键根因（2026-06-15 补充）: 三个组件都用 className="dialog"，而 CSS .dialog 有默认 max-height: 80vh + margin: 16px + overflow-y: auto，在移动端会把弹窗压缩成 80vh 并让整个弹窗滚动，造成内部内容区域高度计算偏小、滚动范围错乱，并与底部固定输入栏叠加到底部操作按钮被遮挡；解决：在每个组件弹窗容器上加 maxHeight: 'none' + margin: 0 + overflowY: 'hidden' 覆盖 CSS 类默认值
    - 智能归类任务6反馈流:
      · 选择卡片后进入 AI 阶段，Toast 显示“AI 正在分析知识点...”
      · 确认整理方案后进入数据库事务阶段，Toast 显示“正在整理卡片...”
      · 本地事务完成后进入云端同步阶段，Toast 显示“正在同步数据到云端...”
      · 成功提示包含整理卡片数、创建/重命名单元数、删除空单元/空分类数、同步结果
      · 错误提示区分网络中断、AI 超时、API Key 配置异常、AI 空结果，并给出重试/检查建议
      · 空分类点击智能整理入口提示“该分类下没有卡片可整理”
      · AI 调用前基于 cards.knowledge_point 去重，减少重复卡片导致的无效整理
  长按防御: ✅ 外层 div onContextMenu + onSelectStart
            ✅ CardItem 组件内置 preventTextMenu
