# 一、系统架构概览

UnitTestMain.jsx (入口页)
  更新题库 → updateQuestionBank()
  单元/分类/章节检测 → 难度选择弹窗(简易/中等/困难/随机) →
    ├─ 简易/中等/困难: updateQuestionBank(difficulty) → /test/unit?difficulty=X
    └─ 随机: checkQuestionBankCompleteness() →
           ├─ 题库完整: 直接跳转 /test/unit?difficulty=random
           └─ 题库不全: 弹出确认对话框 →
                  ├─ 补全题库: updateQuestionBank(undefined) 生成全部难度 → 跳转
                  ├─ 使用现有: 直接跳转（部分知识点可能无题）
                  └─ 取消
  单元/分类/章节复习 → getReviewQuestions() → /test/unit (只查DB，不调AI)

testQuestionService.js (核心出题逻辑)
  模式检测 → isWeakModel() / isStrongModel()
  弱模型路径 → generateQuestionsForWeakModel(targetDifficulty)
  强模型路径 → generateQuestionsForStrongModel(targetDifficulty)
  兼容路径   → runLegacySingleBatch()
  题目矩阵   → analyzeQuestionMatrix(cards, existingQuestions, targetDifficulty)
  题库预检   → checkQuestionBankCompleteness(testType, id) ★新增 2026-06-20
  题目校验   → validateQuestion() + normalizeQuestion() (含难度归一化)
  查重入库   → deduplicateQuestions() → matchQuestionsToCards()

testGradingService.js (AI 评卷逻辑)
  评卷主流程 → gradeTest() (本地评分 + AI 评卷 + 难度加权)
  薄弱点分析 → computeWeakPoints() (兼容 knowledgePoint/knowledge_point/stem/front) ★修复 2026-06-20

# 二、updateQuestionBank 主流程(12步)

步骤1: 获取卡片数据
  - 单元模式: getCardsByUnit(unitId)
  - 分类模式: getAllCardsByCategory(categoryId)
  - 卡片数为 0 则直接返回失败

步骤2: 获取卡片状态
  - getCardStatusesByCategory(categoryId) 获取每张卡片掌握状态
  - 状态等级: new / review / learning / mastered

步骤2.5: 获取分类上下文（分类名称 + 分类目的）★新增 2026-06-19
  - 通过 getCategory(categoryId) 获取分类对象
  - 提取 categoryName = category.name（分类名称）
  - 提取 categoryPurpose = category.purpose（分类目的，如"考研"/"计算机408"等）
  - categoryId 来源:
    · 单元/章节模式: cards[0].categoryId
    · 分类模式: 调用方传入的 id
  - 获取失败时使用空字符串降级（不阻断出题流程）
  - 分类上下文作为必要参数传递给三条出题路径（弱模型/强模型/兼容路径）
  - 由 buildCategoryContext() 拼接为 prompt 段落:
    【分类信息】
    - 分类名称：{categoryName}
    - 分类目的：{categoryPurpose}
    请根据上述分类信息生成符合该学习场景的题目...

步骤3: 获取已有题目
  - 单元模式: getTestQuestionsByUnit(unitId)
  - 分类模式: getTestQuestionsByCategory(categoryId)

步骤4: 过滤过期题目
  - cardId 不在当前卡片集合中(卡片已被删除)
  - createdAt 超过 7 天且 cardId 为空(无主题目)
  - 统计过期数量

步骤5: 三路分流(核心决策)

                    弱模型 isWeakModel(config) → 弱模型路径
  config → 判断 → 强模型 isStrongModel(config) → 强模型路径
                    其他                      → 兼容路径 (单次大批量)

步骤6-8: AI 生成题目(见第三、四、五节)

步骤9: 查重
  - deduplicateQuestions() 基于 stem 的 Jaccard 相似度(阈值 0.85)与已有题目对比

步骤10: 数量限制
  - 单元模式: cards.length × 2
  - 分类模式: MAX_QUESTIONS_CATEGORY = 100

步骤11: 匹配卡片
  - matchQuestionsToCards() 根据知识点/题干的相似度，将题目关联到原始卡片
  - 补全 unitId / categoryId，优先使用 batch 内第一张 card 的 unitId 或调用方 id

步骤12: 入库
  - 构建完整题目对象，包含: id / userId / testType / targetId / type / cardId
    / unitId / categoryId / stem / options / answer / analysis / difficulty(1-3)
    / knowledgePoint / createdAt / updatedAt
  - 调用 addTestQuestions() 批量写入 IndexedDB

# 三、难度体系设计

难度等级(归一化为1-3):
  1 - 简易: 基础概念，记忆为主
  2 - 中等: 理解应用，需要思考
  3 - 困难: 综合分析，深度理解

题目矩阵扩展:
  原矩阵: (cardId, type) → count
  新矩阵: (cardId, type, difficulty) → count

每个知识点最大题目数: 4题型 × 3难度 = 12道题

难度归一化规则(normalizeQuestion):
  - 原始难度 → 数字转换 → 四舍五入 → 限制在[1,3]区间
  - 无效值默认设为 2(中等)

# 四、弱模型路径(Spark Lite)

策略: 多次小批量，每批 ≤ 5张卡片 × 1种题型 × 指定难度
原因: Spark Lite 上下文理解能力有限，大批量会导致质量严重下降

流程:
  1. 按状态优先级排序: new > review > learning > mastered
  2. 构建标记映射表(新增改进7):
     - 每张卡片分配全局唯一标记"标记1"/"标记2"/...
     - cardMarkerMap: cardId → 标记(用于Prompt生成 [mk=标记N] 格式)
     - markerDataMap: 标记 → {cardId, unitId, categoryId}(用于AI返回后直接查表)
  3. 构建题目矩阵 (analyzeQuestionMatrix，含难度维度)
  4. 短路检测: 所有(card, type, difficulty)均已满足 → 直接返回
  5. 分批: 按 LITE_BATCH_SIZE=5 分成多批
  6. 构建任务单:
     - 前2批: 出4种题型(单选/多选/判断/填空)
     - 后续批: 只出2种题型(单选/判断)，节约 token
     - 兜底: 确保每张卡片至少分配1个任务(cardHasTask Map)
  7. 顺序执行每个(batch, type)任务
  8. Prompt 中卡片格式: `卡片N [mk=标记M]: 知识点"..." | 问题="..." | 答案="..."`
     (包含难度约束: `请生成难度为${difficulty}的题目`)
     (包含分类上下文: 分类名称+分类目的注入到 prompt 末尾"只返回 JSON 数组。"前)
  9. AI 返回后解析(标记匹配优先):
     - 优先: 标记匹配 → markerDataMap 直接查表 → 一步到位设置 cardId + unitId + categoryId
     - 兜底: 序号card_N→UUID映射(应对AI未按标记格式返回的情况)
     - 此步后，matchQuestionsToCards 的 cardId 匹配步骤被跳过(已有 unitId/categoryId)
  10. 解析 → 标准化 → 校验 → 汇总
  11. 查重去重

关键参数:
  | 参数                  | 值                 | 说明                       |
  | LITE_BATCH_SIZE       | 5                   | 每批最多 5 张卡片           |
  | maxFullBatches        | 2                   | 前2批出全部4种题型          |
  | 后续批题型             | 单选+判断           | 只出2种，节约token          |
  | MAX_QUESTIONS_PER_CARD_TYPE | 1             | 每卡每种题型最多1道         |
  | 跳过上限              | 5                   | 某卡已有 ≥5 道同类型题则跳过 |

错误控制:
  - 单个(batch, type)任务失败不中断整体
  - 支持 parallel=true 轮转并发模式(默认串行限流)
  - 每个任务最多3次重试(间隔1s/2s/4s)
  - 每个任务完成后回调 onBatchComplete 通知 UI

弱模型特有规则:
  - 每张卡片必须对应1道题(强制锁)
  - 判断题必须是二选一，正确"、一对一"错了
  - 填空题题干必须是陈述句(避免问句形式)，自动检测问句并转换陈述
  - label 禁止用判断词/状态词(正确/错误/待验证等，正确填错)
  - 包含反例/正例示例

# 五、强模型路径(DeepSeek / Spark Pro / 火山 / 千问)

策略: 题型组合分批，每批 ≤ 2-15张卡片 × 1-2种题型组合 × 指定难度
原因: 强模型上下文能力强，让4种题型一次出prompt过长。拆分2组题型组合可大幅降低单次prompt token。

流程:
  1. 选择策略(按模型调参 batchSize + maxTypesPerBatch):
     - DeepSeek/火山/千问: 15张/批，2种题型/批
     - Spark Pro系列: 12张/批，2种题型/批
  2. 按状态优先级排序
  3. 构建标记映射表(改进7)，与弱模型相同的标记方案，cardId → 标记
  4. 构建题目矩阵(含难度维度)
  5. 短路检测: 所有已满足 → 返回
  6. 构建任务单(buildStrongModelTasks，含targetDifficulty参数):
     - 题型组合: objective组(单选+多选)+ binary组(判断+填空)
     - 跳过"已出满"的(card, type, difficulty)
     - 跳过整批
  7. Prompt 中卡片格式: `卡片N [mk=标记M]: ...`(与弱模型统一，含难度约束)
     (包含分类上下文: 分类名称+分类目的注入到 COMMON_RULES 与输入卡片之间)
  8. AI 返回后解析: 标记优先 → 直接查表设置 unitId/categoryId；兜底card_N→UUID
  9. 顺序执行每个任务
  10. 解析(支持对象/数组格式) → 标准化 → 校验 → 格式校验
  11. 查重去重

关键参数:
  | 模型                | batchSize | maxTypesPerBatch | 题型组合1              | 题型组合2              |
  | DeepSeek/火山/千问   | 15        | 2                | single + multi       | true_false + fill    |
  | Spark Pro系列        | 12        | 2                | single + multi       | true_false + fill    |

STRONG_MODEL_STRATEGY 配置:
  deepseek:              { batchSize: 15, maxTypesPerBatch: 2 }
  iflytek-spark-generalv3:{ batchSize: 12, maxTypesPerBatch: 2 }
  iflytek-spark-max-32k: { batchSize: 12, maxTypesPerBatch: 2 }
  iflytek-spark-4.0Ultra:{ batchSize: 12, maxTypesPerBatch: 2 }
  iflytek-spark-pro-128k:{ batchSize: 12, maxTypesPerBatch: 2 }
  volcano:               { batchSize: 15, maxTypesPerBatch: 2 }
  dashscope:             { batchSize: 15, maxTypesPerBatch: 2 }

STRONG_TYPE_GROUPS 配置:
  objective: { name: 'objective', types: ['single_choice', 'multi_choice'] }    
  binary:    { name: 'binary',    types: ['true_false', 'fill_blank'] }

题型规则(完整版):
  | 题型     | 规则                                                          |
  | 单选     | 4个选项 A-D，1个正确；题干含问题或设问句                     |
  | 多选     | 4个选项 A-D，2-4个正确；题干包含"(多选题)"；答案如 "ABD"     |
  | 判断     | 固定2个选项"正确"/"错误"；题干以"判断以下说法是否正确："开头 |
  | 填空     | options=[]；题干用 ____ 标记占位；answer填被占位内容          |

通用规则:
  1. label 必须按各题型规则(选择题A-D，判断题"正确"/"错误")
  2. text 必须是完整陈述句，停止知识点标题/状态词/判断词
  3. 输出 JSON 数组 [{...}] 或对象 { "type": [...] }，每题含 type 字段

错误控制:
  - 强模型路径失败 → 自动降级到 runLegacySingleBatch(兼容路径)
  - 单个批次失败有 Toast 通知
  - 3次重试(1s/2s/4s)

# 六、兼容路径(单次大批量)

策略: 所有卡片 + 所有题型一次性提交
用于: 未知AI服务、强模型路径降级、显示legacy模式

流程:
  1. 构建prompt(buildPrompt，含全部卡片和全部题型，含难度约束，含分类上下文)
  2. 单次 AI 调用
  3. 解析 JSON 数组
  4. 标准化 + 校验
  5. 返回通过校验的题目

# 七、题目矩阵系统(analyzeQuestionMatrix)

目的: 避免重复出题 + 减少 token 浪费

分析维度:
  byCardType:      cardId → { type: { difficulty: count } }  // 每卡每种题型各难度已有几道
  byCardStems:     cardId → { type: { difficulty: [stems] } } // 用于prompt插入"已有题目"
  needTypesByCard: cardId → [{ type, difficulty }, ...]       // 该卡还缺哪些题型难度组合
  totalByType:     { type: count }                           // 本地题库按题型统计
  totalCount:      number                                    // 本地题目总数

使用方式:
  - 弱模型: analyzeQuestionMatrix → 任务单跳过已出满的(batch, type, difficulty)
  - 强模型: buildStrongModelTasks → 按题型组合跳过已出满

关键函数:
  isBatchTypeSatisfied(cardBatch, type, difficulty, matrix)
    → 判断某批卡片在某题型某难度下是否全部已出满，已出满则跳过该任务

  formatExistingQuestionsForBatch(cardBatch, matrix, questionType)
    → 将已有题目信息格式化为 prompt 变量，插入到 prompt 尾部作为"避免重复"参考

# 八、题目校验系统(validateQuestion)

校验维度:
  1. 基础字段校验: type/stem/answer 必填
  2. 题型特定校验:
     - 单选: 4个选项，答案匹配A-D
     - 多选: 4个选项，答案为多个字母组合
     - 判断: options=[{label:'正确'},{label:'错误'}]
     - 填空: options=[]，题干含____
  3. 难度校验: 归一化为1-3，无效值设为2
  4. 格式校验: JSON结构、label格式、text完整性

# 九、分层出题策略(章节→单元→批次)

核心逻辑: 按卡片数量动态决定出题范围
优先级: 章节整体 > 单元 > 分批

策略规则:
  1. 获取章节下所有卡片
  2. 判断是否超过单次调用token上限
     - 未超: 章节统一出题
     - 超过: 按单元分别出题
  3. 单元级别判断
     - 未超: 单元统一出题
     - 超过: 单元内分批(按模型batchSize动态计算)

数据传递:
  - 章节→单元: 通过 unitId 传递上下文
  - 单元→批次: 通过 cardMarkerMap 保持标记映射
  - 批次→入库: 通过 markerDataMap 一步到位设置 cardId/unitId/categoryId

## 2. 题库完整性预检 checkQuestionBankCompleteness()

文件: src/services/testQuestionService.js
函数签名: async function checkQuestionBankCompleteness(testType, id)
完整性标准: 每张卡片 × 4 题型 × 3 难度 = 12 道题目，至少各 1 道

返回值:
  {
    complete: boolean,         // true=题库完整，false=有缺失
    missingCount: number,      // 缺失的 (card, type, difficulty) 组合数
    totalCombinations: number, // 应有组合总数 = cards.length × 12
    existingCount: number,     // 已满足组合数
    cardsCount: number,        // 卡片总数
    missingByCard: Array<{     // 缺失题目的卡片列表
      cardId: string,
      cardFront: string,       // 卡片正面（截断60字符）
      missing: Array<{type, difficulty}>
    }>
  }

调用流程:
  1. 根据 testType 调用 getCardsByUnit/getCardsByChapter/getAllCardsByCategory
  2. 调用 getTestQuestions(testType, id) 获取已有题目
  3. analyzeQuestionMatrix(cards, existingQuestions, undefined) 分析缺失
     (targetDifficulty=undefined 表示检查全部 3 档难度)
  4. 遍历 cards 统计每张卡的缺失组合

## 3. 算法设计：纯 AI 语义审核模式

### 3.1 两步验证流程

步骤1: AI 全权归类 (classifyCardsByCategoryContent)
  - 输入：60 张打乱顺序的卡片
  - 输出：分类→章节→单元三级结构 + 卡片分配
  - 模式：cross-category-auto

步骤2: 纯 AI 语义审核 (verifyCrossCategoryByAI)
  - 输入：步骤1 的分类结果 + 原始卡片
  - 输出：每张卡片的归类审核结果（布尔值）
  - 不使用任何本地关键字匹配

### 3.2 审核模式 vs 独立归类模式

原方案（独立归类模式）：
  - AI 独立对每张卡片重新归类
  - 与步骤1 结果进行名称精确匹配
  - 问题：AI 可能使用不同的章节/单元名称（同义改写），导致精确匹配失败
  - 实测：章节准确率 0%、单元准确率 0%

新方案（审核模式）：
  - AI 直接判断每张卡片在步骤1 结果中的归类是否语义正确
  - 返回 categoryCorrect/chapterCorrect/unitCorrect 布尔值
  - 优势：不依赖名称精确匹配，纯语义判断
  - 实测：章节准确率 100%、单元准确率 98.3%

### 3.3 完整性约束强化

在 assignCardsCrossCategory 的 prompt 中新增"完整性约束（最高优先级）"段落：
1. 每张卡片必须且只能被分配到一个单元中，绝对不能遗漏
2. 每张卡片绝对不能被重复分配到多个单元
3. 所有 cardIndices 合并后必须是 0 到 N-1 的完整集合
4. 输出前请逐一核对每张卡片是否已被分配且仅被分配一次
5. 卡片总数为 N 张，所有单元的 cardIndices 总数必须等于 N

代码层面全局去重：
  - 使用 assignedIndices Set 全局跟踪
  - 跳过已被前面单元分配过的卡片索引
  - 配合原有的 assignCardsByAssociation 兜底分配未分配卡片

## 7. 大数量卡片分批审核优化（2026-06-21 补充）

### 7.1 问题背景

- 所有批次结果合并为 allVerifications 数组
- 单批解析失败时跳过该批，不影响其他批次
- 所有批次均失败时才报错

## 1. 改动背景
