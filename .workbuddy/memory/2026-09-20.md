## 根因：两条独立通道，各有各的墙（之前的诊断反复就是因为把两条混着看）

| | MCP REST 通道 | 本地 git 通道 |
|---|---|---|
| 到 `github.com` | 通 | 通（`curl -x 127.0.0.1:65532` → **200**） |
| 到 `api.github.com` | 通 | **不通（000）** |
| Git Data 写端点 | `refs` ✅ / `blobs` ✅ / **`trees` ❌ 403** | 不需要 |

关键判据：同一代理下 `github.com` = 200 而 `api.github.com` = **000** → 「浏览器能上 GitHub」与「git 能推」是两回事，必须分别验证。

**MCP `trees` 403 已排除「权限问题」**（四条证据）：`create_tag` 成功且 tag 远端可见 / 历史版本 `blobs` 从未 403 / `get_app_identity` 权限齐全 / 官方文档明确 App token + `content` 合法。
→ 只剩「请求体过大触发的边缘拦截」这一解释（`tesseract-core.wasm.js` 4.7MB 等 3 个大文本文件同批，单请求逼近 8MB）。

## 复现「本地 git 直推」的四个必须项（少一个就是"无输出挂死"）

1. **走本机代理** `127.0.0.1:65532`（直连 github.com 完全不通）
2. **`-c http.sslVerify=false`**（代理做 TLS 拦截 → `CRYPT_E_REVOCATION_OFFLINE`；`http.schannelCheckRevoke=false` **无效**）
3. **凭据注入用 `-c credential.helper="store --file=<Windows 路径>"`**（令牌从 `git credential fill` 取，`gho_` OAuth）。⚠️ 别用 `GIT_ASKPASS` + `/tmp` 路径（原生 git 不认 MSYS 路径）；别用 `eval` 拼 `!f() {...}`（括号打断解析）
4. **`GIT_TERMINAL_PROMPT=0`**（不注入凭据时 GCM 会联网刷新令牌 → 该路径不通 → 无限等，表现为超时零输出）

外加：远端有占位提交时用 `git merge --allow-unrelated-histories -X ours`（非破坏性，不 force push）。

**工具坑（已写入 skill）**：核对中文文件名**不能用 `find | comm -23`** —— `git ls-tree` 对非 ASCII
路径输出八进制转义（`"\346\250\241..."`），`find` 输出真实 UTF-8，两者永不相等，
**每个中文文件名都被误报成"缺失"**（英文名不受影响，所以看起来像真缺一半）。
改用 git 三口径分类：`git ls-tree -r HEAD`（已跟踪）/ `git status --porcelain | grep '^??'`（真漏）/
`git status --ignored --porcelain | grep '^!!'`（主动排除）。
