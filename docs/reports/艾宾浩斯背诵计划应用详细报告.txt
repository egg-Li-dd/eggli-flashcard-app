1. 系统概述

1.1 什么是艾宾浩斯遗忘曲线？

德国心理学家赫尔曼·艾宾浩斯在1885年发现了人类记忆的遗忘规律。遗忘曲线表明：
- 学习后的第1天，记忆力保留约33%
- 第2天，保留约28%
- 第6天，保留约25%
- 31天后，保留约21%

核心发现: 如果在即将遗忘的时候进行复习，可以用最少的时间获得最佳的记忆效果。

1.2 本App如何应用艾宾浩斯？

我们使用SM-2算法（Anki等主流记忆软件的核心算法），它基于艾宾浩斯理论，但通过用户的实际复习反馈动态调整复习间隔。

3. 延迟复习惩罚机制

3.1 为什么需要惩罚？

如果用户计划10天后复习某卡片，但他30天后才打开App，这张卡片已经被遗忘了。如果还按原有的公式延长间隔，会导致学习效果下降。

因此，我们设计了4级延迟惩罚系统。

3.3 惩罚规则表（标记「已掌握」时）

延迟等级  延迟条件  对 reps 的影响  对 interval 的影响  对 easeFactor 的影响

按时 onTime  delayDays ≤ 0  reps + 1  interval × easeFactor（正常）  easeFactor + 0.1
轻微 slight  0 < delayDays ≤ 3  reps + 1  min(计算值, prev + 3)  不增加
中等 medium  3 < delayDays ≤ interval  reps 退 1，最小1  ceil(prev × 0.6)  easeFactor - 0.1
严重 severe  delayDays > interval  reps = 1，从新开始  interval = 1 天  easeFactor - 0.15

2026-06-12  +2  slight  reps=4, interval=min(41,18)=18
2026-06-18  +8  medium  reps=2, interval=ceil(15×0.6)=9, easeFactor=2.6
2026-07-01  +21  severe  reps=1, interval=1, easeFactor=2.55

4. 数据存储结构

4.1 主要数据表

表1: cardStatus（卡片学习状态）

位置: `IndexedDB -> db('AIFlashcardsDB_v2').cardStatus`

字段  类型  含义  艾宾浩斯用途

`id`  string  记录ID
`cardId`  string  卡片ID  关联卡片
`categoryId`  string  分类ID  关联分类
`status`  string  mastered/review  手动状态标记
`repetitions`  number  连续成功次数  核心参数
`interval`  number  当前复习间隔（天）  核心参数
`easeFactor`  number  难度系数（1.3-3.0）  核心参数
`nextReviewAt`  number  下次复习时间戳（ms）  决定是否到期
`lastReviewedAt`  number  上次复习时间戳  统计用
`reviewCount`  number  总复习次数  统计用
`mode`  string  操作来源模式  用于模式隔离
`updatedAt`  number  最后更新时间

表2: reviewHistory（复习历史记录）

位置: `IndexedDB -> db('AIFlashcardsDB_v2').reviewHistory`

字段  类型  含义

`id`  string  记录ID
`cardId`  string  卡片ID
`categoryId`  string  分类ID
`wasMastered`  boolean  true=已掌握, false=待掌握
`reviewedAt`  number  复习时间戳
`mode`  string  ebbinghaus/sequential/active/weak/test

用途:
- 计算连续学习天数（streak）
- 历史分析（某卡片在测试中答错了多少次）
- 用户查看单张卡片的复习轨迹
- 云端同步时作为完整历史备份

表3: studyPlans（学习计划配置）

位置: `IndexedDB -> db('AIFlashCardsDB_v2').studyPlans`

字段  类型  含义  默认值

`id`  string  记录ID
`categoryId`  string  分类ID
`chapterId`  string  章节ID（v8新增，支持按章节设置独立计划）  空字符串=分类级计划
`dailyReviewLimit`  number  每日复习上限  50 张
`dailyNewLimit`  number  每日新学上限  20 张
`priority`  string  low/medium/high  medium
`createdAt`  number  创建时间
`updatedAt`  number  更新时间

用途:
- 未来7天预测中，超过 dailyReviewLimit 的日期会标红警告
- 用户可针对不同分类/章节设置不同的学习节奏
- 按 categoryId + chapterId 组合唯一确定一条计划记录

6. 背诵模式隔离系统

6.1 五种背诵模式

模式  mode 值  是否修改 SM-2 参数  是否同步云端  说明

艾宾浩斯  ebbinghaus  ✅ 是  ✅ 是  基于SM-2算法的间隔重复复习
顺序浏览  sequential  ❌ 否，仅更新 status  ❌ 否  按卡片顺序浏览
活跃学习  active  ❌ 否，仅更新 status  ❌ 否  打乱顺序快速复习
薄弱卡片  weak  ⚠️ 缩短 interval，reps不变  ❌ 否  专注待掌握卡片复习
测试评分  test  ❌ 否，仅更新 status  ✅ 是（history同步）  单元/分类检测后评分

6.2 为什么要隔离？

问题: 如果用户在顺序模式下标记了100张卡片为「已掌握」，这些卡片的SM-2参数会被错误地修改——但用户并没有真正按间隔复习。

6.3 薄弱模式的特殊设计

薄弱模式的目标是强化复习，所以当用户在薄弱模式下标记「已掌握」时：
- interval 缩短到原有的 80% → 卡片会更早再次出现
- easeFactor 微增 0.05 → 对用户的掌握给予有限的正面反馈
- reps 保持不变 → 不会因为"在薄弱模式下复习了"就让卡片跳过几个阶段

这是一种「稳健保守」的策略：让薄弱卡片保持在可被复习的范围内，直到用户在艾宾浩斯的正常节奏中证明了自己的掌握程度。
