## 一、临时原始知识点生成机制

### 1.1 数据来源与输入处理

**入口函数**：`extractKnowledgePoints(text, unitNames, config, onProgress)`

**输入来源**：用户输入的文本内容（教材、笔记、考纲等）

**文本分割策略**：
- 弱模型 `MAX_TEXT_LENGTH` = 3000 字符（强模型为 5000）
- 按段落/句子边界智能分块，避免在句子中间切断
- 长文本分割为多个 chunk，每个 chunk 独立调用 AI

```javascript

```

### 1.2 算法处理

**Prompt 模板**：`KNOWLEDGE_POINT_EXTRACTION_PROMPT_WEAK`

核心规则：
1. **一条输入对应一条输出**：每个独立陈述、定义、原理必须单独输出
2. **保留编号与内容**：编号+内容必须一起输出
3. **跳过纯标题**：无实质内容的章节标题跳过
4. **保留原文措辞**：不修改、不总结
5. **不遗漏**：不因"主题相关"就合并

```javascript
// constants.js:247-266
export const KNOWLEDGE_POINT_EXTRACTION_PROMPT_WEAK = `你是考研知识点提取助手...
核心规则（必须严格遵守）：
1. 【一条输入对应一条输出】...
2. 【保留编号与内容】...
...
`
```

```javascript
    }
  }
  
  // 3. 处理未覆盖的知识点（分散到已有主题）
```

### 3.6 Fallback 降级逻辑

当 Spark API 失败时，按知识点顺序均分：

```javascript
// iflytekAi.js:500-516
function sparkFallbackCluster(knowledgePoints, suggestedMax) {
  const groups = []
  const chunkSize = Math.max(2, Math.ceil(knowledgePoints.length / suggestedMax))
  
  for (let i = 0; i < knowledgePoints.length; i += chunkSize) {
    const chunk = knowledgePoints.slice(i, i + chunkSize)
    const topicName = chunk[0].slice(0, 12) || `知识点组${groups.length + 1}`
    groups.push({
      topicName,
      pointIndices: chunk.map((_, j) => i + j),
    })
  }
  return groups
}
```

## 九、弱模型题目生成优化（2026-06-20）

### 9.1 问题背景

39 张卡片仅生成 87 道题（目标 468 道），根因分析：

| 根因 | 影响 | 位置 |
|------|------|------|
| `maxFullBatches = 2` | 75% 的卡片只出 2 种题型（单选+判断），缺失多选+填空 | testQuestionService.js L1107 |
| 任务构造不迭代难度 | 每卡每题型只生成 1 道题，无法覆盖 3 种难度 | testQuestionService.js L1121-1151 |
| `MAX_QUESTIONS_PER_CARD_TYPE = 1` | 限制每题型题数上限为 1，无法达到 3 道目标 | testQuestionService.js L423 |

### 9.2 优化方案：递进式分阶段生成策略

**策略设计**（替代原 `maxFullBatches` 限制）：
- 按难度递进分 3 个阶段，每阶段覆盖全部 4 种题型
- 阶段1（简易 difficulty=1）→ 阶段2（中等 difficulty=2）→ 阶段3（困难 difficulty=3）
- 每阶段内按 (批次, 题型) 构建任务，使用矩阵精确跳过已出齐的组合

**优点**：
1. 确保每张卡片每种题型每种难度都有题（4×3=12 道/卡）
2. 进度可按阶段追踪（33% → 66% → 100%）
3. 某阶段失败不影响已完成的阶段
4. 自然优先级：简易 → 中等 → 困难

### 9.3 核心代码变更

#### 9.3.1 常量调整
```javascript
// 每张卡片每种题型的总上限 = 3 种难度 × 1 道/难度
const MAX_QUESTIONS_PER_CARD_TYPE = MAX_QUESTIONS_PER_CARD_TYPE_DIFFICULTY * 3
```

#### 9.3.2 任务构造（三维迭代）
```javascript
// 按 (阶段/难度, 批次, 题型) 三维迭代
for (let phaseIdx = 0; phaseIdx < allDifficulties.length; phaseIdx++) {
  const currentDifficulty = allDifficulties[phaseIdx]
  batches.forEach((batch, batchIdx) => {
    for (const type of questionTypes) {
      // 矩阵精确跳过：检查该 batch 内哪些卡片还需要该 (type, difficulty)
      const allSatisfied = batch.every(card => {
        const need = matrix.needCombosByCard.get(cid) || []
        return !need.some(c => c.type === type && c.difficulty === currentDifficulty)
      })
      if (allSatisfied) continue
      tasks.push({ phase: phaseIdx, batchIdx, cardBatch: batch, type, difficulty: currentDifficulty })
    }
  })
}
```

#### 9.3.3 三级校验机制
1. **批次内校验**：每批次生成完成后验证题目数量与质量
2. **题型校验**：所有同类型题目生成完成后进行数量汇总验证
3. **总体校验**：全部题目生成完成后进行最终数量核对

#### 9.3.4 自动重试机制
- 失败任务不超过 50% 时自动重试
- 重试使用相同的 (batch, type, difficulty) 参数
- 重试结果替换原失败结果

### 9.4 进度监控系统

`progressStats` 对象包含以下维度：
- `totalTasks / completedTasks / failedTasks`：任务级进度
- `totalGenerated / totalTarget`：题目级进度
- `perType`：各题型生成进度（选择题、填空题等）
- `perDifficulty`：各难度生成进度（简易、中等、困难）
- `perCard`：每卡片题目生成数量统计
- `phaseStatus`：各阶段执行状态（pending/running/completed）

`onBatchComplete` 回调增强为：
```javascript
{
  batchIdx, type, difficulty, phase, generated, error,
  progress: { completed, total, percent, totalGenerated, totalTarget }
}
```

## 十、弱模型跨分类归类优化（2026-06-21）

### 10.1 问题背景

弱模型（讯飞 Spark Lite）在「跨分类 AI 全权归类」（cross-category-auto 模式）场景下存在两大问题：

| 问题 | 现象 | 根因 |
|------|------|------|
| 不能将所选卡片归类到另一个分类中 | 跨分类归类时卡片丢失或归入错误分类 | `planCrossCategoryStructure` 和 `assignCardsCrossCategory` 未对弱模型做分批处理，单次请求超出弱模型处理能力 |
| 不能处理好是否有关联或无关联 | 关联卡片误判、无关联卡片强行归类 | 缺少显式关联检测逻辑，AI 返回不完整时无 fallback |

### 10.2 优化方案：分批处理 + 关联检测 Fallback

#### 10.2.1 弱模型分批规划结构

**新增函数**：`planCrossCategoryStructureWithBatches(cards, config, onProgress)`

```javascript
// aiService.js:8295
const WEAK_CROSS_CATEGORY_BATCH_SIZE = 20  // 弱模型跨分类每批最大卡片数
const MAX_TOKENS_PER_BATCH = 2500           // Token 动态分批阈值

// 触发条件：弱模型 && 卡片数 > 20
if (isSparkLite && cardCount > WEAK_CROSS_CATEGORY_BATCH_SIZE) {
  return await planCrossCategoryStructureWithBatches(cards, config, onProgress)
}
```

**分批策略**：
- Token 动态分批：按卡片内容总字符数估算 token，每批不超过 2500 token
- 每批独立调用 `planCrossCategoryStructure` 生成分类结构
- 使用 `mergeCrossCategoryBatches` 合并多批结果

#### 10.2.2 批次结果合并

**新增函数**：`mergeCrossCategoryBatches(batchResults)`

**合并算法**：
1. 收集所有批次的分类
2. 按语义相似度（阈值 0.3）合并相似分类
3. 合并章节和单元
4. 输出统一的分类结构

#### 10.2.3 弱模型分批分配卡片

**新增函数**：`assignCardsCrossCategoryWithBatches(cards, plan, config, onProgress)`

**流程**：
1. 按 Token 动态分批
2. 从 plan 初始化结果结构
3. 每批调用 `assignCardsCrossCategory` 分配卡片
4. 按分类/章节/单元名称匹配合并批次结果
5. 对未分配的卡片调用 `assignCardsByAssociation` 进行关联检测 fallback

#### 10.2.4 关联检测 Fallback

**新增函数**：`assignCardsByAssociation(cards, indices, categories)`

**关联检测算法**：
```
对每张卡片：
  1. 计算与每个单元的相似度（simpleTextSimilarity）
  2. 综合得分 = 单元相似度×0.6 + 章节相似度×0.25 + 分类相似度×0.15
  3. 提取关键词（extractKeywordsForAssociation）
  4. 关键词匹配加成 = 匹配数 × 0.1
  5. 最终得分 = 综合得分 + 关键词加成
  6. 若最终得分 > 0.05，分配到最佳单元
  7. 否则，放入默认单元（第一个分类的第一个单元）
```

**关键词提取**：`extractKeywordsForAssociation(text)`
- 按标点和空格分词
- 中文词按 2-6 字滑窗提取
- 英文词直接保留
- 去重返回

### 10.3 关联检测 Prompt 增强

在 `planCrossCategoryStructure` 和 `assignCardsCrossCategory` 的 Prompt 中新增「关联性判断」指令：

```
【关联性判断（必须遵守）】
1. 卡片与分类的关联：卡片内容必须与分类主题语义相关
2. 卡片与卡片的关联：同一单元内的卡片应当主题相近
3. 无关联卡片处理：与所有分类都无关的卡片，归入"未归类"单元
4. 跨分类关联：卡片可以归入与原分类不同的新分类（只要语义相关）
```

**问题**：短关键词（如"进制"）作为长关键词（如"二进制"）的子串被重复计分，导致误分类。

**修复**：采用「最长匹配优先」策略
```javascript
function calculateKeywordScore(text, keywords, weight) {
  // 1. 按长度降序排序关键词
  const sortedKeywords = [...keywords].sort((a, b) => b.length - a.length)
  // 2. 匹配后用空格替换，避免子串重复计分
  let tempText = text
  for (const kw of sortedKeywords) {
    while (tempText.includes(kwLower)) {
      score += kw.length * weight
      tempText = tempText.replace(kwLower, ' '.repeat(kwLower.length))
    }
  }
}
```

### 11.7 Spark Lite 准确率优化尝试与最终结论（2026-06-21）

针对 Spark Lite 准确率低的问题，尝试了两种优化方案：

#### 11.7.1 优化方案1：多轮对话策略 + 分批处理优化

**方案设计**：
- 把复杂任务拆分成3轮简单任务
  - Round 1: 分类规划 + 卡片分配到分类（只返回分类名）
  - Round 2: 每个分类内规划章节 + 卡片分配到章节
  - Round 3: 每个章节内规划单元 + 卡片分配到单元
- 分批处理：每批20张卡片（与 aiService.js 的 WEAK_CROSS_CATEGORY_BATCH_SIZE 一致）

**测试结果**：

| 指标 | 优化前（单轮+40张/批） | 优化后（3轮+20张/批） |
|------|---------------------|---------------------|
| 分类覆盖率 | 52.2% | 31.1% ❌ |
| 分类准确率 | 44.4% | 31.1% ❌ |
| 单元准确率 | 0.0% | 0.0% ❌ |
| 耗时 | 34s | 95.2s ❌ |

**优化后反而更差的原因**：
1. **分类碎片化更严重**：Round 1 创建了"计算机基础"、"计算机应用"、"计算机安全"3个分类，但后两个应该是"计算机基础"的子主题
2. **章节过于碎片化**：Round 2 在"计算机应用"下创建了13个章节，每个只有1-2张卡片
3. **卡片丢失更多**：62张未分配（68.9%），多轮对话每轮都可能丢失卡片
4. **耗时翻倍**：3轮对话需要更多 AI 调用

#### 11.7.2 最终结论：Spark Lite 不适合跨分类归类

**根本原因**：Spark Lite 是弱模型，能力上限有限，无论怎么优化 prompt 都无法解决以下核心问题：
1. **分类粒度控制差**：倾向于把每张卡片当成一个分类/章节
2. **结构化输出能力弱**：无法生成规范的3级分类结构
3. **指令遵循能力弱**：即使明确要求"不要把每张卡片当成分类"，仍然会这样做
4. **多轮对话累积误差**：每轮都可能丢失卡片，多轮后丢失更严重

#### 11.7.3 推荐解决方案

| 方案 | 适用场景 | 准确率 | 成本 |
|------|--------|-------|-----|
| **强模型（DeepSeek/Qwen）** | 实际应用 | 预期 80%+ | 付费 |
| **本地关键词分类** | 已知领域测试 | 97.8% | 免费 |
| **Spark Lite** | 不推荐 | 31-44% | 免费 |

**建议**：
1. **实际应用**：使用强模型（DeepSeek/Qwen），在设置中选择对应 AI 服务提供商
2. **快速测试**：使用本地关键词分类（`test-cross-category-v2.mjs`），97.8% 准确率
3. **Spark Lite**：仅用于简单场景（如单分类内的小批量卡片归类），不适合跨分类归类

## 十二、弱模型知识点分类输出格式优化（2026-06-23）

### 12.1 问题背景

弱模型（讯飞 Spark Lite）在知识点归类阶段（路径A多轮分类、路径B两轮分类）使用 JSON 数组作为 AI 输出格式。弱模型结构化输出能力弱，常出现 JSON 格式错误（引号缺失、括号不匹配、多余文字等），导致解析失败回退到本地降级分类，影响归类质量。

### 12.2 优化方案：分组线性表格式

将 AI 输出格式从 JSON 数组改为「分组线性表」（pipe 分隔的纯文本），降低弱模型格式出错概率。解析逻辑改为「线性表优先，JSON 兜底」，确保向后兼容。

### 12.3 涉及函数

| 函数 | 路径 | 位置 | 说明 |
|------|------|------|------|
| `classifyCardsByKnowledgePoints` | 路径B | aiService.js ~L5891 | 弱模型两轮分类（chapter-and-unit / unit-only 两种深度模式） |
| `classifyCardsByKnowledgePointsMultiRound` | 路径A | aiService.js ~L6267 | 弱模型多轮分类（第一轮章节级 + 第二轮单元级） |

### 12.4 新增解析函数

在 `parseLinearNewAssignResult` 函数后面新增两个解析函数：

#### 12.4.1 parseLinearKpResult(raw, depth)
用于路径B（classifyCardsByKnowledgePoints），支持两种深度模式：

| depth | 格式（归入现有） | 格式（创建新） | 返回对象 |
|-------|-----------------|---------------|---------|
| chapter-and-unit | `index\|E\|chapterIndex\|unitName` | `index\|N\|newChapterName\|unitName` | `{index, chapterIndex, unitName, isNew}` 或 `{index, chapterIndex:null, unitName, isNew:true, newChapterName}` |
| unit-only | `index\|E\|unitName` | `index\|N\|unitName` | `{index, unitName, isNew}` |

#### 12.4.2 parseLinearKpMultiRoundResult(raw, round)
用于路径A（classifyCardsByKnowledgePointsMultiRound）：

| round | 格式（归入现有） | 格式（创建新） | 返回对象 |
|-------|-----------------|---------------|---------|
| 1（章节级） | `cardIndex\|E\|chapterIndex` | `cardIndex\|N\|newChapterName` | `{cardIndex, chapterIndex, isNew:false}` 或 `{cardIndex, chapterIndex:null, isNew:true, newChapterName}` |
| 2（单元级） | `cardIndex\|E\|unitIndex` | `cardIndex\|N\|newUnitName` | `{cardIndex, unitIndex, isNew:false}` 或 `{cardIndex, unitIndex:null, isNew:true, newUnitName}` |

### 12.5 解析逻辑（线性表优先，JSON 兜底）

所有解析点统一采用以下模式：
```javascript
// 优先尝试线性表解析
const linearResult = parseLinearXxxResult(raw, depth/round)
if (linearResult) {
  assignments = linearResult
} else {
  console.log('[xxx] 线性表解析失败，回退到JSON解析')
  // 原有 JSON 解析逻辑（提取 [ 到 ] 之间内容用 JSON.parse）
}
```

### 12.6 修改的解析点

| 解析点 | 函数 | 位置 | 解析函数调用 |
|--------|------|------|-------------|
| parseAiResponse | classifyCardsByKnowledgePoints | ~L6003 | `parseLinearKpResult(raw, classificationDepth)` |
| Round1 解析 | classifyCardsByKnowledgePointsMultiRound | ~L6361 | `parseLinearKpMultiRoundResult(raw, 1)` |
| Round2 解析 | classifyCardsByKnowledgePointsMultiRound | ~L6518 | `parseLinearKpMultiRoundResult(raw, 2)` |

### 12.7 向后兼容

- AI 返回线性表格式：线性表解析成功，直接使用
- AI 返回 JSON 格式：线性表解析失败（无 `|` 分隔行或格式不符），自动回退到 JSON 解析
- 两种格式都能正常解析，不影响已有行为
